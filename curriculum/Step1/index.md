# Step 1: クリッカーゲームで遊ぼう（講師用）

## 目標

- コードへの恐怖感をなくす
- 「変えたら動きが変わる」体験をさせる
- Step2への興味・モチベーションをつくる

## タイムライン（目安）

| フェーズ | 時間 | 内容 |
|---|---|---|
| Lv.1 遊ぶ | 15分 | プレイ（10分）→ 発表（5分） |
| Lv.2 眺める | 15分 | 3ファイルの説明（10分）→ 質問（5分） |
| Lv.3 改造 | 30分 | 自由改造（15分）→ 発表（15分） |

## 講師メモ

### Lv.1
- この時点でコードの話は一切しない。ゲームを楽しませることが最優先
- 発表では「クリックでお金が増える」「自動でも増える」あたりが出ればOK

### Lv.2
- コードの細かい説明はしない。「こんな感じのことが書いてある」程度でOK
- `index.html` の `🍙` や `score` など、ゲームと直結している部分を指差して「ここが画面のあそこね」と繋げると効果的
- 「難しそう…」と思わせないのが最重要。「意外とシンプルでしょ」という印象を残す

### Lv.3
- 改造例と期待される気づき

| 改造箇所 | 変化 | 気づいてほしいこと |
|---|---|---|
| `clickPower = 1` → 大きい数字 | クリックで一気に増える | 変数が画面に反映される |
| `price: 15` → `price: 0` | 無料でアイテムを買える | データがゲームの挙動を決めている |
| `name: "強化カーソル"` を変更 | ショップの名前が変わる | HTMLとJSが連動している |
| `🍙` を別の絵文字に | ボタンの見た目が変わる | HTMLを変えると見た目が変わる |

- 「正解はない」を強調する。試して壊れても保存しなければ元に戻せると伝える
- 詰まっている子には答えを教えず「このあたりを変えてみたら？」とヒントだけ出す
- Step1終了時に「Step2でこれら全部の仕組みを学ぶ」とつなぎを入れる
